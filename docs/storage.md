Storage
Storage boundary

The Git repository and operating-system configuration live under:

/opt/homelab

Persistent Homelab data lives outside the Git repository:

/srv/homelab

The Git repository must never contain:

Audiobook files
Ebook files
Application databases
Application metadata
Backups
Secrets
Other persistent runtime state
Directory layout
/srv/homelab/
├── appdata/

│   │   └── metadata/

Audiobook storage

The canonical audiobook storage location is:

/srv/homelab/media/audiobooks/Books

Audiobookshelf's library is configured to use:

/audiobooks

The container mounts the host audiobook directory at /audiobooks.

The Audiobookshelf database stores library item paths relative to /audiobooks. For example:

/audiobooks/Casualfarmer/Beware of Chicken/Beware of Chicken 4 - A Xianxia Cultivation Novel

However, the physical files are stored under:

/srv/homelab/media/audiobooks/Books/Casualfarmer/Beware of Chicken/Beware of Chicken 4 - A Xianxia Cultivation Novel

To preserve the paths stored in the Audiobookshelf database, the deployment creates compatibility symlinks:

/srv/homelab/media/audiobooks/Casualfarmer
    -> /srv/homelab/media/audiobooks/Books/Casualfarmer

This allows both of the following to resolve to the same physical data:

/audiobooks/Casualfarmer/...
/audiobooks/Books/Casualfarmer/...

The symlinks are generated by:

scripts/create-audiobook-links.sh

They must not be replaced with duplicate copies of the audiobook files.

Why the compatibility links exist

The Audiobookshelf database was populated when the library root was:

/audiobooks

and therefore contains paths such as:

/audiobooks/Casualfarmer/Beware of Chicken/...

The physical media was subsequently organized under:

/audiobooks/Books/

Changing the database paths would require modifying persistent application state and risks breaking existing library metadata and playback progress.

The compatibility-link approach preserves the existing database paths while keeping Books/ as the canonical storage location.

Rules
/opt/homelab contains configuration and deployment code only.
/srv/homelab contains persistent runtime data.
Do not store large media files in Git.
Do not store application databases in Git.
Do not store application metadata in Git.
Do not store secrets in Git.
Do not store backups in Git.
Audiobook files belong under /srv/homelab/media/audiobooks/Books.
Compatibility symlinks must point into Books/.
Ebooks belong under /srv/homelab/media/ebooks, with the Calibre library metadata.db at that directory's root.
Application containers should mount persistent state from /srv/homelab.
Storage setup should be automated by repository scripts where practical.
The M920 should be recoverable by cloning the repository and rerunning the bootstrap/deployment scripts.
Ownership

The audiobook media is currently owned by the sean user/group on the host.

The Audiobookshelf container accesses the files through its container mount and runs its application process as the node user.

Do not recursively change ownership of existing media without first verifying the container's UID/GID requirements.

Verification

To verify the physical audiobook location:

find /srv/homelab/media/audiobooks/Books -maxdepth 2 -type d | sort

To verify the compatibility links:

find /srv/homelab/media/audiobooks \
    -mindepth 1 \
    -maxdepth 1 \
    -type l \
    -printf '%f -> %l\n' \
    | sort

To verify Audiobookshelf can access a known book:

docker exec audiobookshelf test -f \
"/audiobooks/Casualfarmer/Beware of Chicken/Beware of Chicken 4 - A Xianxia Cultivation Novel/Beware of Chicken 4 A Xianxia Cultivation Novel Beware of Chicken, Book 4.m4b" \
&& echo "BOOK 4 FILE: OK" \
|| echo "BOOK 4 FILE: MISSING"
